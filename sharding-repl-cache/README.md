# Кластер MongoDB с шардированием, репликацией и кэшированием Redis (Задание 3)

## 📋 Архитектура кластера
* **Приложение:** 1 контейнер `pymongo_api` (работает на порту `8080`).
* **Кэш-слой:** 1 контейнер `redis` (высокоскоростной кэш в оперативной памяти).
* **Роутер:** 1 контейнер `mongos_router` (точка входа для приложения на порту `27020`).
* **Конфигурационный сервис:** Реплика-сет `config_server` из 3 нод (`configSrv1`, `configSrv2`, `configSrv3`).
* **Шард 1:** Реплика-сет `shard1_set` из 3 нод (`shard1-1`, `shard1-2`, `shard1-3`).
* **Шард 2:** Реплика-сет `shard2_set` из 3 нод (`shard2-1`, `shard2-2`, `shard2-3`).

## 🚀 Быстрый запуск

Вся инфраструктура, сборка приложения, инициализация кластера, наполнение тестовыми данными и замер скорости кэша запускаются одной командой.

1. Откройте терминал в корневой папке проекта.
2. Дайте права на выполнение всем Bash-скриптам автоматизации:
   ```bash
   chmod +x scripts/*.sh
   ```
3. Запустите главный управляющий скрипт:
   ```bash
   ./scripts/run_all.sh
   ```

## 🛠 Что делает автоматизация
Скрипт `run_all.sh` пошагово выполняет следующие действия:
1. Запускает 11 Docker-контейнеров в фоновом режиме (включая API-приложение и Redis).
2. Ожидает стабилизации сети и запускает `init_config.sh` для сборки реплика-сета конфигурационных серверов.
3. Запускает `init_shards.sh` для сборки отказоустойчивых реплика-сетов первого и второго шардов.
4. Ожидает выбора главных нод (Primary) в шардах и запускает `init_router.sh`.
5. Роутер `mongos` подключает оба реплика-сета шардов, включает шардирование для базы `somedb` и настраивает хэшированное распределение коллекции `helloDoc` по полю `name`.
6. Генерирует и записывает **1000 тестовых документов**.
7. Автоматически вызывает скрипт проверки распределения данных по шардам `check_shards.sh`.
8. Запускает автоматический нагрузочный тест кэша `check_cache.sh` для эндпоинта `/{collection_name}/users`.

## 📈 Проверка распределения данных и работы кэша

### 1. Распределение документов по шардам
В конце Шага 5 скрипт выведет детальный отчет. Благодаря хэшированию, данные делятся между реплика-сетами практически поровну:
```text
Shard shard2_set contains 50.8% data, 508 documents...
Shard shard1_set contains 49.2% data, 492 documents...
```

### 2. Тестирование скорости кэширования (Шаг 6)
Эндпоинт получения пользователей содержит искусственную задержку в 1 секунду. При повторном запросе данные мгновенно отдаются из оперативной памяти Redis, что увеличивает скорость ответа в десятки раз:
```text
📥 1. Отправка первого запроса (чтение из MongoDB)...
   ⏱️ Время выполнения: 1.097 сек (запрос шел в базу + sleep)
--------------------------------------------------------
🚀 2. Отправка повторного запроса (чтение из кэша Redis)...
   ⏱️ Время выполнения: 0.057 сек (мгновенный ответ из памяти)
```

## 🧹 Полная очистка проекта
Чтобы остановить все контейнеры и полностью удалить созданные тома (volumes) с жесткого диска для повторного чистого запуска, выполните:
```bash
docker compose down -v
```
